# Parity record

What Port's application measures, element by element, for the parts AEP
reproduces. A builder builds against it; a comparison measures the same
elements in AEP and reports every difference.

A part is done when the record holds the part and every sub-part to the
leaves, including what appears only on interaction; when every value was
read from Port's running application; and when AEP matches every value or
states a reason for the exception. A value that was not read is listed as
not measured, never filled in. Two things are not copied: the colour
palette and the font family. Colours are recorded to tell which role each
plays ([`colour-roles.md`](./colour-roles.md)).

## Parts

| Part                   | What                                                                                                            | Inventory                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `shell`                | The frame of every page: rail, panel, top bar, content surface                                                  | [`shell/inventory.md`](./shell/inventory.md)                               |
| `data-model`           | The `Data model` page of the context lake, graph view                                                           | [`data-model/inventory.md`](./data-model/inventory.md)                     |
| `catalog-page`         | The catalog page of one blueprint: its header, toolbar and table                                                | [`catalog-page/inventory.md`](./catalog-page/inventory.md)                 |
| `entity-page`          | One entity's page: its header, tabs and their content                                                           | [`entity-page/inventory.md`](./entity-page/inventory.md)                   |
| `data-model-dialogs`   | The data model builder's dialogs: blueprints, properties of each kind, relations, permissions and the simulator | [`data-model-dialogs/inventory.md`](./data-model-dialogs/inventory.md)     |
| `governance-users`     | The `Users & Teams` page: its two tabs, their toolbars, tables and row menus                                    | [`governance-users/inventory.md`](./governance-users/inventory.md)         |
| `governance-audit-log` | The `Audit Log` page: its tabs, tables, expanded entries, filters and empty state                               | [`governance-audit-log/inventory.md`](./governance-audit-log/inventory.md) |
| `connectors-page`      | The `Connectors` page of the context lake: its sections, cards and the first level of its dialogs               | [`connectors-page/inventory.md`](./connectors-page/inventory.md)           |

The home page is no part. It is an exception to parity
([RFC 0012](../../../rfcs/0012-agentic-home/README.md#parity)): the
reference's home is a dashboard, and the structure of AEP's is AEP's own
by that RFC. No record of the reference's home is its measure; its
components are held to their own records where they have one.

Each part is a directory:

- `inventory.md`: the checklist of every sub-part, saying where it is
  recorded, or why it is not, or that it is a separate part for a later
  pass; the wording and order of what the part shows; its behaviour; its
  exceptions; and, generated by `tools/inventory.py`, one line per measured
  element.
- `base.json`: every element of the part in its resting state.
- `<state>.json`: one file per state (a hover, a keyboard focus, an open
  menu, another area). A difference holds only what differs from the state
  named in its `base` field. A whole record of a state has no `base` and
  holds every element of what it records, as `base.json` does
  (`shell/search-all.json`, `shell/org-menu-open.json`, each dialog of
  `data-model-dialogs`). Other states may be differences from it.
- `custom-properties.json`: the CSS custom properties that the rules
  matching the base elements refer to, with their values. They show Port's
  scale (`--spacing: .25rem`, `--text-sm`, …).
- `shell/scrollbars.json`: the global scrollbar rules and the computed
  values of the scrollbar pseudo-elements.
- `data-model/behaviour.json`: pan and zoom readings, and the first level of
  the dialogs that are separate parts.
- `data-model/graph.json`: the whole graph in its resting state, read in the
  same session as the part's state files (they share one `capturedAt`, the
  session's start). Not a state file. It holds:
  - `viewportTransform` and `counts`;
  - `nodes`: every node from the graph library's store, with `position`,
    `width` and `height` in graph coordinates (before the zoom), `rank`,
    the relations of its blueprint, and under `dom` the element's
    `transform`, size and handles (`id`, side, source or target);
  - `edges`: every drawn edge in DOM order, with `source`, `target`,
    `sourceHandle`, `targetHandle`, `dashed`, `isVirtualEdge`, the path
    `d`, `pathStyle`, `markerStart`, `markerEnd`, and `chip` (the position
    attributes of its container, its size, its text and its icon's hash),
    plus `directRelationFromSourceToTarget`;
  - `storeEdges`: every edge the store holds, drawn or hidden;
  - `markers`: the two marker definitions;
  - `filterList`: every row of the filter list in drawn order (`kind`,
    `label`, `y` from the top of the scrolled content, `height`,
    `hiddenMark`) and the measures of its virtualisation;
  - `hiddenControl`, `expandedTeam` (the size the store gives the expanded
    node, the size it draws, the zoom), `pickerHints` (hint text and
    picture of every property type), `fit` and `edgeRuleReplay`;
  - `fromEarlierSession`: `lockedRows`, `connector` and `scorecards`, read
    in an earlier session and kept with that session's time;
  - `blueprints`: identifier, title and relations of every blueprint the
    page holds.
- `pictures/picker/`: the 19 hint pictures of the property type picker
  (`<name>.png`, 320 by 320, named as the application names them), fetched
  as public static files from the paths the picker's `img` elements carry,
  and `index.json` with each picture's type label, path, pixel size, byte
  size and SHA-256.
- `icons/`: the drawings whose hash matched no file of the icon sets, one
  `<hash>.svg` per drawing holding the `svg` element as the browser
  serialises it, and `index.json` naming for each the first record element
  that shows it. The hash is that of the markup inside the element, as in
  `icon.hash`.

## Record file

```json
{
  "part": "shell",
  "state": "rail-item-hover",
  "base": "base",
  "capturedAt": "2026-11-19T13:57:40.123Z",
  "source": "https://demo.port.io/~/context-lake/data-model",
  "viewport": { "width": 1728, "height": 941 },
  "theme": "light",
  "canvas": {},
  "elements": [],
  "notMeasured": [{ "id": "…", "reason": "…" }]
}
```

- `base` is absent in a whole record: `base.json`, and a state file that
  holds its state in full. In a difference it names the state the file is
  a difference from: usually `base`, sometimes another state (the hover of
  a menu item is a difference from the open menu).
- `canvas` exists in `data-model` files only: the graph's zoom and
  translation, its background pattern and its edge markers.
- `source` is the address without its query string.

### Element in a base file

`base.json`, and a state file that is a whole record (it has no `base`).

```json
{
  "id": "shell/rail/link[Context lake]/span/icon",
  "tag": "svg",
  "role": "",
  "name": "",
  "text": "",
  "box": { "x": 18, "y": 366, "width": 20, "height": 20 },
  "style": { "display": "block", "width": "20px" },
  "icon": { "inline": true, "viewBox": "0 0 24 24", "hash": "1a2b3c4d" },
  "attrs": { "aria-hidden": "true" },
  "sourceHint": { "testid": "…", "class": "…" }
}
```

- `tag`: the tag name in lower case, or `::before` / `::after` for a
  pseudo-element that has content (it has no `box`: the browser gives
  none; its size is in `style`).
- `role`: the `role` attribute, else the role HTML implies for common tags
  (`a` link, `button`, `nav` navigation, `hr` separator, `ul` list,
  `h1`–`h4` heading, `input` textbox, …), else empty.
- `name`: the accessible name as far as it can be read without the
  accessibility tree: `aria-label`, else the text of `aria-labelledby`, else
  `alt`, `title`, `placeholder`, else, for buttons, links, tabs, menu items,
  options and headings, the element's text. At most 80 characters.
- `text`: the element's own text (its direct text nodes; for a leaf, all its
  text). At most 200 characters.
- `box`: `getBoundingClientRect()` in CSS pixels of the viewport, one
  decimal. To compare positions, subtract the box of the part's root (the
  first element of `base.json`): the demo shows two bars above the shell
  that an ordinary session does not have.
- `style`: computed values, by CSS property name. Always present:
  `display`, `position`, `box-sizing`, `width`, `height`, `min-width`,
  `max-width`, `min-height`, `max-height`, the four `padding-*`, the four
  `margin-*`, `gap`, `row-gap`, `column-gap`, `flex-direction`, `flex-wrap`,
  `align-items`, `align-self`, `justify-content`, `flex-grow`,
  `flex-shrink`, `flex-basis`, `overflow-x`, `overflow-y`, the four
  `border-*-width`, `border-*-style`, `border-*-color`, the four corner
  radii, `box-shadow`, `outline-width`, `outline-style`, `outline-color`,
  `outline-offset`, `background-color`, `background-image`, `color`,
  `opacity`, `font-family`, `font-size`, `font-weight`, `font-style`,
  `line-height`, `letter-spacing`, `text-transform`, `text-align`,
  `text-decoration-line`, `text-decoration-style`, `text-decoration-color`,
  `white-space`, `text-overflow`, `cursor`, `transition-property`,
  `transition-duration`, `transition-timing-function`, `transition-delay`,
  `transform`, `z-index`, `visibility`, `pointer-events`, `vertical-align`.
  Shorthands are recorded as their longhands (`flex`, `overflow`, `padding`,
  `border`, `text-decoration`, `transition`). Present when they apply:
  `grid-template-columns`, `grid-template-rows`, `grid-auto-flow` (grid
  containers); `top`, `right`, `bottom`, `left` (positioned elements);
  `background-size`, `background-position`, `background-repeat` (with a
  background image); `backdrop-filter`, `filter` (when set); `fill`,
  `stroke`, `stroke-width`, `stroke-dasharray`, `stroke-linecap`,
  `stroke-linejoin`, `marker-start`, `marker-end` (SVG elements); `content`
  (pseudo-elements).
- `icon`, on an `svg` or `img`: for an inline SVG, `inline: true`, `width`,
  `height`, `viewBox`, `strokeWidth` (the computed stroke width of its first
  stroked shape, or `none (filled shapes)`), `fillAttr`, `shapes` (how many
  shapes it draws), `hash` (a short hash of its markup; the markup is not
  kept) and `name` (whatever names it: `aria-label`, `<title>`, a data
  attribute, its class). For an image, `inline: false`, the rendered and
  natural sizes, the file name and a hash of it.
- `attrs`: the state attributes the element carries (`aria-expanded`,
  `aria-selected`, `aria-current`, `aria-haspopup`, `aria-hidden`,
  `disabled`, `tabindex`, `type`, `placeholder`, …) and, for a link, its
  `href` without query string.
- `sourceHint`: Port's `data-testid` and class list. Not for comparison: it
  finds the element again when re-measuring, and the class list shows the
  utility classes behind the values.

### Element in a state file

In a state file that is a difference (it has a `base`), every element has
a `change`, and `tools/inventory.py` refuses a file with one that has
none; an element of a whole record has none. "The base" below is the state
the file names in `base`:

- `"modified"`: the element exists in the base too. Only the fields that
  differ are present; `style` holds only the properties that differ. A
  property that stops applying in the state (the insets of an element that
  is no longer positioned) is listed in `notMeasured`.
- `"added"`: the element exists only in this state (a tooltip, a menu, a
  revealed control). It is recorded in full, like a base element.
- `"removed"`: the element of the base is absent in this state. Only `id`.

An element that is not listed is the same as in the base. When a modal is
open, Port sets `pointer-events: none` on everything behind it; that change
is kept on the part's root only.

### Ids

An id is a path, `part/…/segment`, unique within a part.

- A landmark has a fixed id given by hand: `shell/rail`, `shell/panel`,
  `shell/topbar`, `shell/main/page-surface`, `data-model/header`,
  `data-model/filter`, `data-model/canvas`, `data-model/controls`,
  `data-model/node[Team]`, `data-model/edge[service to group][dashed]`.
- An element with a role or a landmark tag is a named segment,
  `role[accessible name]`, attached to the nearest landmark or named
  element above it, skipping the plain wrappers between them:
  `shell/rail/link[Context lake]`,
  `shell/panel/navigation[Catalog]/list/link[Action run]`.
- Any other element is its parent's id plus a segment: `icon` for an `svg`,
  `image` for an `img`, `text` for a leaf that holds text, else the tag
  name.
- When two ids would be equal, the later one in document order gets `~2`,
  `~3`, ….
- Something rendered outside the part's root while a state is shown hangs
  under `part/overlay[state]`: `shell/overlay[help-menu-open]/menu/menuitem[Updates]`.

To match an AEP element with the record, give it the id in a
`data-parity` attribute. The comparison measures that element with the
same properties and compares them to the record: everything except colour
values and `font-family`, which map by role. Inside the graph's viewport,
boxes are scaled by `canvas.zoom`; compare computed sizes there, or boxes
divided by the zoom.

## How it was measured

On `https://demo.port.io` (Port's public demo, signed in as a demo
administrator), in Chrome, light theme, viewport 1728 by 941 CSS pixels,
device pixel ratio 2. The viewport is the one the browser window had: the
window also held other tabs and was not resized.

Nothing in Port was changed: no save, create, delete or update; dialogs were
opened and closed with Escape with nothing typed. No cookie, storage, token
or request header was read, and the page made no request on the record's
behalf.

States were produced for real: hover with the pointer, open with a click,
close with Escape. For keyboard focus, Tab was pressed once and focus was
then moved to the element with `focus()`; a focus state is recorded only if
the element matched `:focus-visible`. Tab order and arrow keys were checked
with real key presses and are described in the inventories.

## Re-measuring

`tools/measure.js` is the library the record was made with. Its part
definitions hold Port's selectors, so a change in Port's markup shows up
there first. The file is the consolidated form of what was run step by step
in the page. Its general functions (capture, difference, overlays, focus,
export) were run again on a small test page; its two part definitions were
not run again on Port after the consolidation.

1. Open the page in Chrome at the viewport above and paste
   `tools/measure.js` into the console.
2. Give the landmarks their ids: `__parity.parts.shell.init()` (or
   `__parity.parts['data-model'].init()`). Repeat it whenever the page
   re-creates the part: after going to another area, pinning or unpinning
   the panel, switching between graph and cards.
3. With the pointer over an empty spot of the page:
   `__parity.snap('shell', 'base', null)`.
4. For each state in the inventory: produce it, wait a second for
   transitions to end, then `__parity.snap('shell', '<state>')`. Pass the
   name of another state as third argument when the state is a difference
   from it, and `true` as fourth to keep the ids of an overlay that is
   still open. For a focus state:
   `await __parity.focusSnap('shell', '<state>', element)`.
5. `__parity.vars('shell:base')` gives the custom properties.
6. Export `__parity.files`: by hand with
   `copy(JSON.stringify(__parity.files))`; from an automated session that
   cannot copy text, with `await __parity.pack(...)` and `__parity.show(n)`
   per frame, a lossless capture of the top-left 1680 by 900 CSS pixels of
   the viewport for each frame, and `tools/decode.py`.
7. Write each file as `<part>/<state>.json` with 2-space indentation, then
   run `python3 tools/inventory.py <part>` to rewrite the checklist and the
   element count of the part's inventory, from every file of the part.
   `python3 tools/inventory.py --check <part>` writes nothing and fails
   when the inventory is not what the tool writes.
